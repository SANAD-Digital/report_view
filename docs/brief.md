# الموجز: محرك عرض التقارير Report View

## الهدف
صفحة تقارير احترافية بنمط AG Grid Enterprise، تعمل فوق تقارير النظام الحالية (Query Report و Script Report) دون تعديلها، وتقدّم:
- عرض الجدول والشجرة والتجميع متعدد المستويات مع مجاميع لكل مجموعة
- تحليل Pivot ورسوم بيانية
- فلاتر متقدمة وعروض محفوظة ومشاركة
- تصدير Excel وطباعة PDF احترافيين
- كل ذلك مع احترام كامل لصلاحيات Frappe

المسار: `/app/report-view/<report_name>`، مع زر دخول من صفحة query-report القياسية.

## المبدأ المعماري
| الطبقة | أين تعمل | لماذا |
|---|---|---|
| تشغيل التقرير | الخادم عبر `frappe.desk.query_report.run` | نفس الصلاحيات ونفس النتائج |
| التطبيع (المحوّل) | المتصفح | يحوّل رد `query_report.run` إلى جدول حقائق بمخطط أنواع صريح |
| التجميع والتحليل والفلترة والفرز والحقول المحسوبة | المتصفح، داخل Web Worker بمحرك Perspective | مرونة كاملة دون تعديل تقارير بايثون، وأداء على مئات آلاف الصفوف |
| عرض الجدول واللوحات والتفاعل | المتصفح: `regular-table` وكود خاص بنا | الشكل والسلوك بنمط AG Grid Enterprise حسب التصميم |
| الإثراء (حقول إضافية من المستندات المرتبطة) | الخادم عبر `frappe.get_list` | الصلاحيات |
| التصدير والطباعة | الخادم | فحص `can_export` و `print`، وتنسيق كامل، وعربية سليمة |

## النطاق
داخل النطاق: كل ما ورد أعلاه، و DocType للإعدادات، و DocType للعروض المحفوظة، وإعداد جاهز لميزان المراجعة.
خارج النطاق: تعديل تقارير موجودة، Report Builder، تقارير Custom Report المحفوظة (تُدرس لاحقاً)، التعديل المباشر داخل الجدول.

## المكتبات
| المكتبة | الإصدار | الاستخدام |
|---|---|---|
| `@finos/perspective` | 3.x مثبّت بالضبط (آخر مستقر عند القرار: 3.8.0) | محرك الحساب فقط، في Web Worker عبر `perspective.worker()`: `group_by`، `split_by`، `aggregates`، `filter`، `sort`، `expressions` |
| `regular-table` | مثبّت بالضبط (آخر مستقر عند القرار: 0.9.1) | عرض الجدول الافتراضي؛ كل خلية ورأس يُنسَّق برمجياً عبر `addStyleListener` |
| ECharts | 5.x | الرسوم، تُغذّى من `view.to_columns()` |
| openpyxl | ما يأتي مع Frappe | تصدير Excel |
| أداة PDF في Frappe | حسب الإصدار | الطباعة |

تُثبَّت مكتبات JS عبر npm في `package.json` الخاص بالتطبيق، وتُحمَّل عند فتح الصفحة فقط. طريقة تحميل Perspective وملفات WASM داخل Frappe تحددها تجربة المحور «و» في المرحلة 1 (`docs/research/perspective-experiments.md`).

**ممنوع في الواجهة النهائية:** `perspective-viewer` ولوحة إعداداته وثيماته وإضافاته (ومنها d3fc)؛ شكلها غير مناسب لمستخدمينا. الواجهة كلها نبنيها نحن حسب التصميم.

**غير مستخدمة:** Tabulator و Arquero. ذكرهما في إصدارات سابقة من الوثائق كان خطأً في فهم المتطلبات (قرار 2026-10-01).

## المرفقات (في `reference/`)
- `reference/prototype/`: نموذج منطقي يعمل ببيانات JSON. مرجع للمنطق فقط: المحوّل، وعقد التطبيع، ونموذج التصدير، وشكل الشاشات، والعروض الجاهزة. لا يُنقل منه أي كود عرض أو تجميع. المقابلة مع Perspective في `docs/research/prototype-mapping.md`.
- `reference/design/`: تصدير نموذج Claude Design. المرجع البصري والتفاعلي الوحيد. أي اختلاف عنه يحتاج سبباً مكتوباً.

## أهداف الجودة (قابلة للتعديل من صاحب المشروع)
| المعيار | الهدف |
|---|---|
| الإصدار المدعوم | ما يُكتشف في المرحلة 0 |
| الحد الأقصى للصفوف في المتصفح | يُحدَّد من نتائج تجارب الأداء في المحور «و» (10 آلاف، 100 ألف، 500 ألف صف). إلى أن تُنجز التجارب يبقى الحد المؤقت 50,000. ما فوق الحد: رسالة واضحة بخيارات فعلية (ADR-009) |
| زمن أول عرض لتقرير بـ 10,000 صف | أقل من 2 ثانية بعد وصول البيانات |
| زمن إعادة التجميع (`group_by` على مستويين) عند الحد الأقصى للصفوف | أقل من 1 ثانية |
| استهلاك الذاكرة | كل `view` و `table` يُحذف بـ `delete()` عند عدم الحاجة؛ لا تسرب بعد 20 تبديل تقرير |
| مطابقة الإجماليات مع الأصل | 100% في كل تقارير الاختبار |
| المتصفحات | آخر إصدارين من Chrome و Edge و Firefox و Safari |

## المصطلحات
- **جدول الحقائق (facts):** صفوف التقرير بعد التطبيع؛ بلا صفوف مجاميع، وفي التقارير الشجرية الحسابات الفرعية فقط مع أعمدة مستويات (`level_1`، `level_2`، …) مولّدة من سلسلة الأب. يُحمَّل في `perspective.table()` بمخطط أنواع صريح.
- **إعداد العرض (view config):** ما تبنيه اللوحات وتمرره للمحرك: `group_by`، `split_by`، `columns`، `aggregates`، `filter`، `sort`، `expressions`.
- **حالة العرض (view state):** كل ما يحدد شكل العرض الحالي (العرض، الفلاتر، التجميع، الأعمدة، التحليل)، قابلة للحفظ والمشاركة.
- **إعداد التقرير:** طبقتان: تسجيل JS للمنطق (`report_view.register`)، و DocType `Report View Settings` للتهيئة بدون كود. التقرير بلا إعدادات يعمل تلقائياً.
