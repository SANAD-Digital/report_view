## 1. تحميل WASM داخل Frappe

### 1.1 ما في الحزمة فعلاً (3.8.0)
- `package.json` ← `exports["."].default = ./dist/esm/perspective.js`. الواجهة (من `dist/esm/perspective.browser.d.ts`): `init_server(wasm)`، `init_client(wasm)`، `worker(worker?)`، `websocket(url)`.
- `dist/esm/perspective.js` (32,590 بايت): JS فقط، **لا يستورد أي `.wasm`**، ولا `import.meta`، ولا `await` على المستوى الأعلى. يجب استدعاء `init_server` و `init_client` يدوياً.
- `dist/cdn/perspective.js`: مثله لكنه يستدعي `init_server(fetch(new URL("../wasm/perspective-server.wasm", import.meta.url)))` بنفسه.
- `dist/esm/perspective.inline.js` (3,741,389 بايت): الملفان مضمّنان base64، وينتهي بـ `await V.init_server(...); await V.init_client(...)` على المستوى الأعلى.
- الـ worker في كل النسخ **مضمَّن كنص** ويُنشأ هكذا: `new Worker(URL.createObjectURL(new Blob([...])), {type: "module"})`. يمكن تمرير worker خاص: `perspective.worker(Promise.resolve(new Worker(url, {type: "module"})))` (`src/ts/perspective.browser.ts`، دالة `worker`)، والملف الجاهز لذلك `dist/cdn/perspective-server.worker.js` (5,839 بايت).
- ملفا wasm «ذاتيا الاستخراج» (`pro_self_extracting_wasm`): مضغوطان داخلياً. `extract.mjs` يستعمل `WebAssembly.instantiateStreaming` عند تمرير `Response`، ولذلك يلزم `Content-Type: application/wasm`.

### 1.2 (أ) عبر esbuild الخاص بـ Frappe
bundle تجريبي مؤقت `report_view/public/js/rv_perspective_probe.bundle.js` (نسخته في `tests/experiments/perspective/exp1a_probe_esm.bundle.js.txt`)، والأمر `bench build --app report_view`.

| ما جُرّب | النتيجة | الدليل |
|---|---|---|
| `import server_wasm from "@finos/perspective/dist/wasm/perspective-server.wasm"` | **فشل**: `No loader is configured for ".wasm" files` | `artifacts/perspective/exp1a-build-wasm-import.log` |
| `import perspective from "@finos/perspective"` (JS فقط) | **نجح**: 45.26KB | `exp1a-build-esm.log` |
| السابق + `import "regular-table"` + `import(url)` ديناميكي | **نجح**: 95.69KB (وضع التطوير). `import(url)` بقي كما هو في المخرج | `exp1a-build-esm-regular-table.log` |
| السابق مع `--production` | **نجح**: 64.16KB (20,001 بايت بـ gzip -9) | `exp1a-build-production.log` |

لماذا:
- لا يوجد `loader` في إعداد Frappe: `apps/frappe/esbuild/esbuild.js:317-337` (`get_build_options`) يحدد `entryPoints`، `target`، `bundle`، `plugins` فقط. والهدف ثابت `es2017` في السطر 89 ولا يُغيَّر من التطبيق.
- نسخة esm من Perspective لم تُفشل البناء على es2017، فلم تتكرر مشكلة المرحلة 3: لا `for await` ولا `await` على المستوى الأعلى فيها، و `BigInt` مستعمل كاستدعاء دالة (`BigInt(x)`، `BigInt.asUintN`) وهو ما يقبله esbuild على هذا الهدف.

التحقق في المتصفح من أصل الموقع: الصفحة `bundle_check.html` تحمّل الـ bundle المبني بوسم `<script src>` عادي (وهو بالضبط ما يفعله `frappe.require`: `apps/frappe/frappe/public/js/frappe/assets.js:26-35`)، ثم تنشئ جدولاً و `view` وتربطه بـ `<regular-table>`.
النتيجة: `ok: true`، 4 خلايا مرسومة، أول خلية «نقد». الدليل: `exp1a-bundle-check-site.json` (تطوير) و `exp1a-bundle-check-site-production.json` (إنتاج).

**ملاحظتان عن `bench build` نفسه (وُجدتا أثناء التجربة):**
1. `bench build` يعيد رمز خروج 0 حتى عند فشل esbuild.
2. عند فشل جزء الـ JS، ينجح بناء CSS في الوقت نفسه ويحذف ملف CSS القديم (`build-cleanup.js:9-10`)، لكن `assets.json` لا يُحدَّث لأن `Promise.all` رُفض (`esbuild.js:247` ثم `:140`). النتيجة: `assets.json` يشير إلى ملف CSS محذوف إلى أن ينجح بناء لاحق. حدث ذلك فعلاً في التجربة وأُصلح ببناء ناجح فوراً.

**ما يختلف في Desk ولم يُختبر:**

- **شرط القبول «مثبتة عملياً داخل صفحة Desk» لم يتحقق حرفياً.** يلزم مستخدم اختبار (معلّق من المرحلة 0).

### 1.6 الطريقة الموصى بها
JS المكتبتين داخل bundle عادي يبنيه Frappe ويُحمَّل بـ `frappe.require`؛ ملفا wasm وملف الـ worker أصول ثابتة من نفس الأصل؛ والـ worker ننشئه نحن لنملك مقبضه.

```js
// report_view/public/js/rv_engine.bundle.js  — يبنيه esbuild الخاص بـ Frappe (es2017) بلا أي إعداد إضافي
import perspective from "@finos/perspective"; // dist/esm/perspective.js: لا wasm ولا top-level await
import "regular-table";

const VERSION = "3.8.0"; // يساوي الإصدار المثبّت؛ يكسر كاش /assets (سنة) عند الترقية
const BASE = "/assets/report_view/node_modules/@finos/perspective/dist";

perspective.init_server(fetch(`${BASE}/wasm/perspective-server.wasm?v=${VERSION}`));
perspective.init_client(fetch(`${BASE}/wasm/perspective-js.wasm?v=${VERSION}`));

let engine = null;

export function get_engine() {
	if (!engine) {
		const worker = new Worker(`${BASE}/cdn/perspective-server.worker.js?v=${VERSION}`, { type: "module" });
		engine = perspective.worker(Promise.resolve(worker)).then((client) => ({ client, worker }));
	}
	return engine;
}

export async function dispose_engine() {
	if (!engine) return;
	const { client, worker } = await engine;
	engine = null;
	client.terminate();
	worker.terminate(); // الطريقة الوحيدة لإعادة ذاكرة WASM للنظام (§3.3)
}
```

مجرَّب: `init_*` مرة واحدة، ثم ثلاث دورات «إنشاء worker ← جدول ← view ← حذف ← terminate» (137ms، 58ms، 69ms). الدليل: `exp1-recommended-lifecycle.json`. و `?v=` لا يغيّر `Content-Type` (تحقق بـ curl).

لماذا worker من ملف لا Blob:
1. نملك المقبض فنستطيع `worker.terminate()`. مع `perspective.worker()` الافتراضي لا مقبض.
2. لا يحتاج `blob:` في `worker-src` إن فُعّلت CSP لاحقاً (§4.2).

ما يجب حسمه في المعمارية: مصدر ملفات wasm في الإنتاج. المجرَّب هو مسار `node_modules` المربوط رمزياً. البديل: نسخ الملفين إلى `public/` بسكربت `build` في `package.json` (Frappe يشغّل `yarn build` لكل تطبيق: `esbuild.js:511-540`). لم يُجرَّب البديل.

## 2. العربية و RTL في `regular-table`

الصفحة `pages/rtl.html` + `pages/lib/rtl_page.js`، والمشغّل `exp2_rtl.mjs`. البيانات: حقائق ميزان المراجعة الحقيقية (16 ورقة) في `perspective.table()` بمخطط صريح، و `view` بـ `group_by` على المستويات. رأس مجمّع بمستويين (الرصيد الافتتاحي / حركة الفترة / الرصيد الختامي × مدين / دائن)، وبثلاثة مستويات و96 عموداً مع `split_by: ["account"]`. عمود الشجرة هو `row_headers`. التلوين بـ `addStyleListener` + `getMeta` + `metadata`.

لكل حالة: لقطة أولى، تمرير أفقي 50%، 100%، تمرير أفقي وعمودي، ثم عجلة الفأرة. ولكل خطوة مسبار هندسي (موضع العمود المثبّت بالبكسل، ونافذة الأعمدة التي طلبها الجدول). الملف: `artifacts/perspective/exp2-chromium-probes.json`. اللقطات: `artifacts/perspective/exp2-chromium-*.png` (30 صورة).

### 2.1 النتائج

| الحالة | العمود المثبّت | التمرير الأفقي | الرؤوس المجمّعة | الحكم |
|---|---|---|---|---|
| LTR إنجليزي (`ltr-en-split`) | يسار، ثابت (`left=1` في كل الخطوات) | يعمل، النافذة 0→40→89 | محاذاة | **نجح** |
| RTL أصلي: `dir="rtl"` فقط (`rtl-native-split`) | يمين في البداية، ثم **يخرج من الإطار** (`right=-2685` عند 50%) | **لا يعمل**: النافذة تبقى `[0,10]` | محاذاة في اللقطة الأولى | **فشل** |
| RTL + تعديل `scrollLeft` فقط (`rtl-shim-split`) | يخرج من الإطار | النافذة تتغير صحيحاً (40، 89) لكن **الإطار فارغ** | — | **فشل** |
| **RTL + المحوّلان (`rtl-shim2-split`)** | يمين، ثابت (`right=1` في كل الخطوات) | يعمل، النافذة 0→40→89، آخر عمود يظهر، العجلة تعمل بالاتجاه الصحيح | محاذاة (3 مستويات) | **نجح** |
| بديل 1: عكس الأعمدة برمجياً (`rtl-reverse-split`) | **لا يوجد**: عمود الحساب يصير آخر عمود بيانات ويغيب عند التمرير | يعمل | محاذاة | مرفوض |
| بديل 2: `scaleX(-1)` (`rtl-flip-split`) | يمين، ثابت | يعمل، لكن اتجاه العجلة الأفقية **معكوس** | محاذاة | يعمل بعيوب |
| بديل 3: sticky خاص | هو الجزء الثاني من «المحوّلين» | | | مدموج في `shim2` |

سبب فشل RTL الأصلي (من كود 0.9.1):
1. الجدول يحسب نافذة الأعمدة من `this.scrollLeft` على أنه من 0 إلى قيمة موجبة (`src/ts/scroll_panel.ts:173` و `:874-882`). في حاوية RTL يعيد المتصفح قيماً من 0 إلى سالبة، فتبقى النافذة عند العمود 0.
2. الجدول مثبّت داخل Shadow DOM بـ `position: sticky; left: 0` (`src/less/container.less:36` و `src/ts/scroll_panel.ts:609`). في حاوية RTL موضعه الطبيعي عند الحافة اليمنى، وقيد `left` لا يُفعَّل، فيتحرك مع المحتوى ويخرج.

### 2.2 الحل المجرَّب («المحوّلان»، 12 سطراً)
```js
// (1) regular-table يقرأ/يكتب scrollLeft بافتراض LTR
const desc = Object.getOwnPropertyDescriptor(Element.prototype, "scrollLeft");
Object.defineProperty(rt, "scrollLeft", {
	configurable: true,
	get() { return -desc.get.call(this); },
	set(v) { desc.set.call(this, -v); },
});
// (2) قيد sticky على اليمين بدل اليسار (Shadow DOM مفتوح: scroll_panel.ts:572)
const clip = rt.shadowRoot.querySelector(".rt-scroll-table-clip");
clip.style.right = "0px";
clip.style.removeProperty("left");
```
يُطبَّقان على عنصر الجدول الخاص بنا فقط (لا تعديل للمكتبة ولا لـ Frappe)، وفي RTL فقط.

تقييم اللقطات (فتحتها وراجعتها):
- `exp2-chromium-rtl-shim2-split-0-initial.png`: عمود الحساب على اليمين، الأعمدة من اليمين لليسار، الإزاحة الشجرية من اليمين، الأرقام LTR بمحاذاة صحيحة.
- `…-1-x50.png`، `…-2-x100.png`، `…-3-x50-y100.png`: العمود المثبّت باقٍ على اليمين، والرؤوس الثلاثة متراصفة مع الأعمدة بعد التمرير في الاتجاهين.
- `…-dark-*.png`: الوضع الداكن سليم.
- `…-390-*.png`: على عرض 390px العمود المثبّت يأخذ 331px من عرض الحاوية 370px (أسماء الحسابات طويلة)، فلا يبقى للأرقام إلا 38px. يلزم حد أقصى لعرض العمود المثبّت على الموبايل (قرار تصميم؛ `Mobile.dc.html` يعالجه بمبدّل الأشرطة).
- `rtl-shim2-split-path-*.png`: `row_headers` متعددة الأعمدة مع دمج `rowspan` تعمل في RTL، لكنها تستهلك العرض كله (4 أعمدة × 260px). العمود الشجري الواحد هو الخيار العملي.

### 2.3 عيوب البدائل
- **عكس الأعمدة (1):** `row_headers` تُرسم دائماً في بداية جدول LTR (اليسار)، فلا يمكن استخدامها. عمود الحساب يصير عمود بيانات أخيراً غير مثبّت (`rtl-reverse-split-0-initial.png`: لا يظهر اسم أي حساب). ويلزم عكس كل الفهارس في نموذج البيانات.
- **`scaleX(-1)` (2):** يعمل بصرياً (`rtl-flip-split-*.png`)، لكن: (أ) `regular-table` يكتب `textContent` في كل رسم، فيلزم إعادة إنشاء عنصر داخلي معكوس لكل خلية في كل رسم؛ (ب) اتجاه العجلة الأفقية معكوس (في المسبار: `wheel(+400)` هو ما حرّك الأعمدة نحو النهاية، والمستخدم في RTL يمرّر بقيمة سالبة) ويحتاج اعتراضاً؛ (ج) أي عنصر منبثق داخل الحاوية ينعكس؛ (د) يتعارض مع CSS التمرير الجزئي الذي يستعمل `transform` على الخلايا.

### 2.4 عمود مثبّت في النهاية
`regular-table` لا يدعمه: لا يرسم إلا الأعمدة داخل النافذة، فلا يفيد `position: sticky` على عمود غير مرسوم.
المجرَّب: عنصر مستقل فوق حافة النهاية (`#pinend`)، تُحاذى صفوفه مع صفوف الجدول داخل `addStyleListener`، وقيمه من `view` ثانٍ بنفس `group_by` (عمود `expressions`: `"closing_debit" - "closing_credit"`).
النتيجة: **يعمل** في RTL و LTR (`rtl-shim2-split-pinend-*.png`، `ltr-en-split-pinend-1-x50.png`)، بثمن: `view` إضافي، وقراءة هندسة الصفوف في كل رسم، وهامش في نهاية منطقة التمرير حتى لا يغطي آخر عمود حقيقي.

### 2.5 ما لم يُختبر في RTL
- **Safari:** `regular-table` يعالج عجلة الفأرة يدوياً في Safari فقط (`src/ts/events.ts:128-158`) بجمع `scrollLeft + deltaX`. مع المحوّل الأول يُتوقع انعكاس الاتجاه هناك. لم يُختبر (لا WebKit).
- **التمرير الجزئي** (`dist/css/sub-cell-scrolling.css`): لم يُستعمل، والتمرير في التجربة يتحرك بعمود كامل. المتغير `--regular-table--transform-x` يحتاج عكس الإشارة في RTL على الأرجح.
- اللمس: معالجات اللمس اليدوية معطّلة في 0.9.1 (`events.ts:25`، `IOS_DISABLE_OVERSCROLL = false`)، فالتمرير باللمس أصلي. لم يُختبر على جهاز.

Some features may not work, and performance may be degraded.` متى غاب `window.chrome` (`node_modules/@finos/perspective/src/rust/utils/console_logger.rs:92-98` و `:216-221`). ظهر في headless shell (لا `window.chrome`) واختفى في Chromium الكامل. أي أنه **سيظهر دائماً في Firefox و Safari**، وهذا يصطدم بقاعدة «لا تحذيرات في console». لا خيار في المكتبة لإسكاته.

### 4.2 CSP
الخادم لا يرسل CSP اليوم (§1.4، §1.5). لمعرفة ما يلزم إن فُعّلت، خُدِّمت صفحة التحميل محلياً بعدة سياسات (`exp4_csp.mjs`، الملف `exp4-csp-chromium.json`):

| السياسة (`default-src 'self'` + …) | esm + Blob worker | esm + ملف worker | inline |
|---|---|---|---|
| بلا CSP | نجح | نجح | نجح |
| `script-src 'self'` | فشل | فشل | فشل |
| `script-src 'self' 'wasm-unsafe-eval'` | فشل (الـ worker من `blob:` مرفوض) | **نجح** | فشل |
| + `worker-src 'self'` | فشل | **نجح** | فشل |
| + `worker-src 'self' blob:` | نجح | نجح | نجح |
| `script-src 'self' 'unsafe-eval'; worker-src 'self' blob:` | نجح | نجح | نجح |

- الحد الأدنى للطريقة الموصى بها (ملف worker من نفس الأصل): **`script-src 'self' 'wasm-unsafe-eval'`** فقط. `worker-src` يرث من `script-src` إن لم يُحدَّد.
- الـ worker الافتراضي (Blob) يحتاج فوق ذلك `worker-src 'self' blob:`.
- الخادم المحلي أرسل CSP على صفحة HTML فقط. الـ worker المحمَّل من ملف يخضع لترويسات رد ملفه هو؛ إن أُرسلت CSP على `/assets` أيضاً فيلزمها `'wasm-unsafe-eval'` كذلك. لم يُجرَّب.

### 6.4 هل يعمل تعبير على القيم المجمَّعة؟ **لا.**
- النتيجة (د) تثبتها: التعبير يُحسب لكل صف إدخال ثم يُجمَّع ناتجه، فأعطى مجموع صوافي الأوراق لا صافي المجموع.
- `sum("d") - sum("c")` يجتاز `validate_expressions`، لكن `sum` داخل التعبير دالة صفّية متعددة المعاملات لا مجمِّع: `sum("amount", "qty")` أعاد `[11.5, null, null, 1, 5.1, 6.2]` أي مجموع عمودين لكل صف (§7).
- المجمِّع `abs sum` على عمود الصافي يعطي `|Σ الصافي|` لكل مجموعة، وهو يساوي مدين الأب + دائنه (true لكل الآباء)، لكنه لا يحدد الجانب. لا يوجد مجمِّع يعطي `max(Σ, 0)`.

### 6.5 البدائل بدقة

**(i) فصل الإشارة في طبقة العرض.**
- المحرك: `expressions: {net_open: '"opening_debit" - "opening_credit"', net_close: '"closing_debit" - "closing_credit"'}` مع `sum`؛ و `debit` و `credit` بـ `sum` مباشرة.
- خارج المحرك لكل صف مجموعة: `مدين = max(net, 0)`، `دائن = max(−net, 0)`؛ وللإجمالي: جمع صفوف العمق 1.
- يطابق 100% للآباء وللإجمالي. **يخالف قاعدة «لا حساب خارج المحرك»** (عمليتا `max` وجمع الجذور). يحتاج موافقة صريحة.
- يُبقي `view.expand/collapse` وكل مزايا `group_by`.

**(ii) صفوف التقرير كما هي.**
- جدول فيه كل الصفوف (آباء وأوراق) بأعمدة `rid`، `depth`، `anc_1..anc_k` (سلف كل صف في كل مستوى)، و `view` مسطح مفروز بـ `rid`. لا `group_by` ولا تجميع.
- يطابق 100% بالبناء، ويعرض صف `'Total'` كما أعاده التقرير.
- الطي ليس `view.collapse` بل فلتر في المحرك: `filter: [["anc_1", "not in", [...المطوية]], ["anc_2", "not in", [...]]]`. مجرَّب: 17 صفاً متوقعاً = 17 فعلياً (القيمة `null` تمرّ من `not in`).
- القيد: الآباء أرقام جامدة. أي فلتر في المتصفح أو إعادة تجميع لا يعيد حسابها. يصلح للعرض الشجري «كما هو» فقط.

**(iii) جدول ثانٍ مجمَّع مسبقاً.**
- `view` أول بـ `group_by` يحسب الصافي الموقَّع لكل عقدة. تُنقل صفوفه (بلا أي حساب في JS) إلى جدول ثانٍ فيه صف لكل عقدة. على الجدول الثاني: `expressions` مثل `max("net_close", 0)` و `max(0 - "net_close", 0)`، وهي هنا صفّية = لكل عقدة. الإجمالي: `view` بفلتر `depth == 1` و `sum`.
- يطابق 100% للآباء وللإجمالي، **وكل الحساب داخل المحرك**.
- الكلفة: جدول و `view` إضافيان لكل إعادة تجميع، والعرض يقرأ جدول العقد المسطح فيكون الطي بفلتر الأسلاف كما في (ii) لا بـ `view.expand/collapse`.

### 6.6 القاعدة المقترحة
1. المحوّل يحمّل الأوراق، ويعرّف لكل زوج مدين/دائن «رصيدي» عمود صافٍ موقَّع بتعبير في المحرك. أعمدة الحركة تُجمع مباشرة.
2. العرض الشجري «كما هو» (الافتراضي لتقرير شجري بلا فلاتر متصفح): البديل **(ii)**. يطابق الأصل بالبناء، وهو الحالة الوحيدة التي لها أصل تُقارَن به.
3. عند إعادة التجميع أو الفلترة في المتصفح لتقرير فيه أزواج صافية: البديل **(iii)** إن بقيت قاعدة «لا حساب خارج المحرك» بلا استثناء، أو **(i)** إن قبل صاحب المشروع استثناءً موثقاً لفصل الإشارة (أبسط بكثير ويبقي `expand/collapse`). **القرار لصاحب المشروع.**
4. التقارير بلا أزواج صافية (`show_net_values=0`، وكل تقرير مجاميعه جمعية): `group_by` + `sum` مباشرة، يطابق 15 من 15 والإجمالي.
5. قاعدة N4.7 في المعمارية (إجمالي الشجرة = مجموع الجذور) تأكدت: الإجمالي هو مجموع صفوف العمق 1 بعد التصفية، لا صف الجذر الذي يعيده `group_by` (وهو 0 للصافي في ميزان متوازن).

### 6.7 الشجرة غير المنتظمة (وُجدت أثناء التجربة)
حسابات الميزان ليست كلها بالعمق نفسه (`4110 - مبيعات` في العمق 2 وغيرها في العمق 3). `group_by` يضع كل الأوراق في عمق واحد، فتظهر عقد وسيطة قيمتها `null`:
`["4000 - الإيرادات", "4100 - إيراد مباشر", null, "4110 - مبيعات"]` (عقدتان `null` من 34 صفاً؛ وإذا وُضعت الورقة نفسها في أعمدة المستويات: 5 صفوف `null`، كل واحد آخر ابن لورقة).
هذه الصفوف يجب إخفاؤها. البديلان (ii) و (iii) لا يتأثران لأنهما يعرضان جدول عقد مسطحاً. مع (i) يلزم طيّ آباء تلك العقد بعد كل `set_depth`، أو فهرسة في نموذج البيانات.

## 7. الدوال المطلوبة

`run.html?exp=exp7` و `exp7b` و `exp7c` (الملفات `exp7-functions.json`، `exp7b-followups.json`، `exp7c-lifecycle.json`). جدول اختبار من 6 صفوف فيه `null` في كل نوع، وأسماء أعمدة عربية: `اسم الحساب` و `المستودع - الرئيسي`.

### 7.1 المجمِّعات
مجموعة A فيها `amount = [10.5, null, 4.5]`.

| المجمِّع | موجود؟ | نتيجة A | ملاحظة |
|---|---|---|---|
| `sum` | نعم | 15 | يتجاهل `null` |
| `avg` / `mean` | نعم | 7.5 | يقسم على غير الفارغ |
| `count` | نعم | 3 | **عدد الصفوف**، لا عدد غير الفارغ |
| `distinct count` | نعم | 3 | يعدّ `null` قيمة |
| `min` | نعم | 4.5 | سليم |
| `max` | نعم | **`null`** | **خطأ مع وجود `null`** (والإجمالي `null` أيضاً) |
| `high` | نعم | 10.5 | الأعلى الصحيح |
| `low` | نعم | **0** | **خطأ مع `null`** (يعامله 0) |
| `median` | نعم | 10.5 | مريب مع `null` |
| `sum abs`، `abs sum`، `sum not null` | نعم | 15 | `abs sum` = `|Σ|` |
| `unique` | نعم | `null` | يعيد القيمة إن كانت واحدة، وإلا `null` |
| `dominant`، `first`، `last`، `first by index`، `last by index`، `any`، `join`، `distinct leaf` | نعم | | |
| `stddev`، `var`، `q1`، `q3`، `last minus first`، `high minus low` | نعم | | `q3` و `high minus low` يعيدان `null` مع `null` |
| `pct sum parent`، `pct sum grand total` | نعم | 121.95 | نسبة من الأب / الإجمالي |
| `weighted mean` (`["weighted mean", ["qty"]]`) | نعم | | |
| `sum` على عمود نصي | — | خطأ `Unexpected coltype` | المحرك بقي يعمل |

الافتراضي عند عدم التحديد: `sum` للأرقام و `count` لغيرها (مثبت).
**للأدنى والأعلى استعمل `min` و `high`**، لا `max` ولا `low`.

### 7.2 القيم الفريدة مع العدّ
`view({group_by: [col], columns: ["id"], aggregates: {id: "count"}, sort: [["id", "desc"]]})` ثم `to_columns({start_row: 1})`: أعاد `[["نقد", 2], ["دائنون", 1], ["مبيعات", 1], ["مدينون", 1], [null, 1]]`. ومع بقية الفلاتر يعمل (`filter` في الإعداد نفسه). 5000 قيمة من 500 ألف صف: 676ms (§3.1).

### 7.3 النوافذ
- `to_columns({start_row, end_row, start_col, end_col})` و `to_json(...)` يعملان؛ `end` غير شامل؛ النافذة خارج المدى تعيد مصفوفات فارغة بلا خطأ.
- `column_paths({start_col, end_col})` يعمل. `__ROW_PATH__` يُضاف دائماً في `view` مجمَّع ولا يُحسب ضمن فهارس الأعمدة.
- `index: true` يضيف `__INDEX__`، و `id: true` يضيف `__ID__`، و `leaves_only: true` يعيد الأوراق فقط.
- `num_rows()`، `num_columns()`، `dimensions()`، `get_min_max(col)` تعمل.
- التاريخ والوقت يعودان أرقاماً (ملي ثانية UTC): `"2026-01-15"` ← `1768435200000`. نافذة 50 صفاً: ~1ms حتى على 500 ألف.

### 7.4 الطي والفتح
`view` بمستويين (9 صفوف):
- `set_depth(0)` ← 4 صفوف (الجذر + المستوى الأول). `set_depth(1)` ← 9. أي `set_depth(n)` يُظهر حتى العمق `n+1`.
- `collapse(1)` أعاد 2 (عدد الصفوف المخفية) و `num_rows` صار 7. `expand(1)` على صف مفتوح أعاد 0.
- `collapse(0)` يطوي كل شيء إلى صف الجذر.
- `group_by_depth: 1` في الإعداد يحدّ العمق من البداية.
- الفهرس المطلوب هو فهرس الصف في العرض الحالي، ويتغير بعد كل طي/فتح.

### 7.5 `null`
- مسار المجموعة `[null]`، ويأتي آخر الترتيب. في `split_by` اسم العمود `"null|amount"` (نص).
- `not in [A]` و `!= 'YER'` **يشملان** صفوف `null`. `> 0` و `< 100` **يستثنيانها**. `is null` و `is not null` يعملان (المعامل الثالث `null`).
- الحساب مع `null` يعطي `null` (`"amount" + 1`). `is_null("amount") ? 0 : "amount"` يعمل.

### 7.6 أسماء أعمدة غير ASCII
| الاستخدام | النتيجة |
|---|---|
| اسم عمود في المخطط، `columns`، `group_by`، `split_by`، `sort`، `filter` | **يعمل** (مع المسافات و ` - `) |
| مرجع عمود في تعبير: `length("المستودع - الرئيسي")` | يعمل (ويعيد **عدد البايتات** لا الحروف: 6 لـ «نقد») |
| اسم عربي للتعبير نفسه (`"الصافي - محسوب"`) | يعمل |
| `concat("اسم الحساب", ' - ', "currency")` | يعمل |
| مقارنة عمودين نصيين عربيين | يعمل |
| **نص حرفي غير ASCII داخل تعبير**: `"اسم الحساب" == 'نقد'` | **يفشل**: `Invalid string token` (وكذلك `'é'`؛ و `'ن…'` لا يُفسَّر) |
| قيمة فيها `\|` مع `split_by` | المسار `"x\|y\|q"uote"` **ملتبس** (الفاصل نفسه) |
| اسم عمود فيه `"` داخل تعبير | يفشل. اسم فيه `'` يعمل |

الأثر: أي شرط على قيمة عربية يُكتب في `filter` (يعمل) لا في `expressions`. والفلاتر السريعة المبنية بتعابير منطقية يجب أن تقارن بقيم ASCII أو بأعمدة مساعدة من المحوّل.

### 7.7 ترتيب النصوص العربية
33 كلمة (همزات، تاء مربوطة، ألف مقصورة، تشكيل، تطويل، أرقام هندية، لاتيني، فارسي):
- `sort` في المحرك = ترتيب وحدات الترميز (= ترتيب بايتات UTF-8 هنا). **لا يطابق `Intl.Collator("ar")`**: المحرك يضع اللاتيني أولاً ثم `ء، آدم، أحمد، ؤ، إبراهيم، ئ، ابتسام…` و «مُحمد» بعد «محمود»؛ والـ Collator يضع الأرقام ثم `ء، ؤ، ئ، آدم، ابتسام، إبراهيم، أحمد…` و «مُحمد» بين «محمد» و «محمود»، واللاتيني آخراً.
- **ترتيب `group_by` الافتراضي = الترتيب نفسه** (أبجدي بوحدات الترميز)، لا ترتيب الإدخال.
- الحل المجرَّب: عمود مفتاح رقمي يولّده المحوّل بـ `Intl.Collator`. الفرز المسطح به يطابق الـ Collator، وللمجموعات `aggregates: {key: "min"}` مع `sort: [["key", "asc"]]` يطابق أيضاً.
- للشجرة: `aggregates: {rid: "min"}, sort: [["rid", "asc"]]` أعاد ترتيب التقرير الأصلي بالضبط (31 حساباً).

### 7.8 الفلاتر
| الفلتر | النتيجة |
|---|---|
| `in`، `not in` | يعملان |
| `contains`، `begins with`، `ends with` | تعمل مع العربية. `contains` **غير حساس لحالة الأحرف** |
| `==`، `!=`، `>`، `>=`، `<`، `<=` | تعمل |
| نطاق أرقام | فلتران (`>=` و `<=`). **لا يوجد `between`** (`Unknown filter operator string`) |
| تاريخ: `["posted", ">=", "2026-02-01"]`، و `==`، ونطاق | يعمل بنص ISO |
| وقت وتاريخ | يعمل |
| منطقي `== true` | يعمل |
| `filter_op: "or"` | **غير موثوق**: صحيح مع مقارنات رقمية (`[1, 4]`)، وأعاد `[]` مع `==` نصي ولو بشرط واحد |

بدائل «أو»: `in` على عمود واحد، أو عمود `expressions` منطقي ثم `["keep", "==", true]` (يعمل، بقيم ASCII فقط).

### 7.9 عمود الإجمالي مع `split_by`
`column_paths` أعاد `["USD|amount", "USD|qty", "YER|amount", "YER|qty", "null|amount", "null|qty"]`: **لا عمود إجمالي**. يلزم `view` ثانٍ بنفس `group_by` بلا `split_by` (مجرَّب، والقيم صحيحة). صف الإجمالي (الجذر) موجود في الاثنين. ترتيب أعمدة التحليل بـ `sort: [["amount", "col desc"]]` يعمل.

### 7.10 `update` و `replace`
- `update` بمفتاح `index`: تحديث جزئي لعمود واحد يعمل، والإدراج يعمل، و `remove([id])` يعمل.
- `replace(rows)`: يستبدل كل الصفوف، والـ `view` القائم يبقى حياً ويتحدّث، و `on_update` يُستدعى. عمود غير موجود في المخطط يُتجاهل بصمت.
- `clear()` يُفرغ الجدول ويبقي المخطط والـ `view`.

### 7.11 العملات المختلطة
`aggregates: {currency: "unique"}` يعيد العملة إن كانت واحدة في المجموعة و `null` إن اختلطت (A: `null`، B: `"YER"`). و `distinct count` يعطي عددها. المحرك يجمع المبالغ بلا اعتبار للعملة؛ الكشف والتنبيه مسؤوليتنا بهذين المجمِّعين.

### 7.12 مفاجآت يجب أن تدخل المعمارية
1. **تحويل الأنواع عند التحميل صامت أو قاتل:**
   - `float`: `""` ← 0، `"abc"` ← 0، `"1,234.5"` ← 1. بلا خطأ.
   - `integer` هو int32 ويلتف بصمت: `2147483648` ← `-2147483648`، `3000000000` ← `-1294967296`. و `2.9` ← 2.
   - `date`: `"05-01-2026"` يُقرأ **2026-05-01** (شهر-يوم). `""` أو تاريخ غير صالح ← خطأ `Could not coerce to date`.
   - `boolean`: `"Yes"` و `""` ← خطأ. `string`: الرقم `1.5` ← `"1.500000"`.
   - **قيمة واحدة سيئة تُسقط الدفعة كلها** (0 صف محمَّل من 3).
   المحوّل يجب أن يحوّل كل قيمة إلى نوعها الصحيح أو `null` قبل التحميل، وأن يعامل `Int` في Frappe كـ `float` (أو يتحقق من المدى).
2. بلا مخطط صريح، الاستنتاج من أول صف ثم الفشل عند الثاني (`Could not coerce to date`). يؤكد قاعدة المخطط الصريح.
3. **دورة الحياة:**
   - `table.delete()` وله `view` مفتوح ← يُرفض بـ `Cannot delete table with views`، **ثم يصير مقبض الجدول ميتاً**: أي نداء لاحق عليه لا ينتهي أبداً ويرمي `null pointer passed to rust` كخطأ صفحة، والجدول يبقى في المحرك. الاسترجاع المجرَّب: `client.open_table(name)` ثم `delete()`.
   - `view.delete()` مرتين، أو أي نداء على `view` محذوف ← **لا ينتهي أبداً** (لا يُرفض).
   - `table.delete({lazy: true})` لا ينتهي حتى يُحذف آخر `view`؛ انتظاره قبل حذف العروض = تعليق دائم.
   - أي نداء بعد `client.terminate()` لا ينتهي أبداً.
   مدير دورة الحياة يجب أن يحفظ حالة كل مقبض ويمنع النداء على المحذوف (غلاف بسيط مجرَّب في `exp7c.js`)، وأن يحذف العروض قبل الجدول دائماً، وأن يعطي الجداول أسماء صريحة.
4. `max` و `low` خاطئان مع `null` (§7.1).
5. `filter_op: "or"` غير موثوق مع النصوص (§7.8).
6. النصوص الحرفية غير ASCII ممنوعة في التعابير (§7.6).
7. مجاميع الأعداد العشرية ليست دقيقة: `0.1 + 0.2 = 0.30000000000000004`، و `12.299999999999999`. التنسيق عبر `frappe.format` يخفيها، لكن أي مقارنة (مثل «مدين = دائن» في بطاقات التوازن) تحتاج تسامحاً بدقة العملة.
8. `count` يعدّ الصفوف لا القيم غير الفارغة، و `length()` يعدّ البايتات.

بناء جملة التعابير (ExprTk): `if (c, a, b)` و `c ? a : b` و `if (c) a; else b;` تعمل. `if (c) a else b` بلا فاصلة منقوطة **يفشل**. `max(x, 0)`، `abs`، `round`، `is_null`، `bucket("posted", 'M')`، `month_of_year`، `day_of_week`، `string()`، `upper`، `concat`، `percent_of`، `and`/`or` تعمل. `contains()` غير موجودة كدالة تعبير.

### طريقة التحميل
- bundle عادي يبنيه Frappe يستورد `@finos/perspective` و `regular-table` (يُبنى على es2017 بلا أي تعديل، تطويراً وإنتاجاً)، ويُحمَّل بـ `frappe.require`.

- `init_server(fetch(...))` و `init_client(fetch(...))` مرة واحدة، و worker ننشئه نحن ونُنهيه عند مغادرة الصفحة. الكود في §1.6.
- لا تُستعمل النسخة inline، ولا استيراد `.wasm` عبر esbuild.
- **معلّق:** إثباتها داخل Desk بمستخدم حقيقي.

### RTL
- **يعمل بمحوّلين صغيرين** على عنصر الجدول (§2.2): عكس إشارة `scrollLeft`، ونقل قيد sticky إلى اليمين داخل Shadow DOM. لا عكس للأعمدة ولا `scaleX`.
- المحوّلان يعتمدان على تفاصيل داخلية في 0.9.1، فيبقى الإصدار مثبّتاً بالضبط، ويُعاد اختبار RTL عند أي ترقية.
- عمود مثبّت في النهاية: بعنصر مستقل فوق الجدول و `view` ثانٍ (§2.4)، إن بقي مطلوباً في التصميم.
- عمود شجري واحد في `row_headers` لا عدة أعمدة مدموجة. وعلى 390px يلزم حد لعرض العمود المثبّت.

### الحد الأقصى للصفوف
- **100,000 افتراضياً، وسقف صلب 200,000** (§3.4).
- التحميل على دفعات ≤ 50,000 صف، وبصيغة أعمدة.
- `worker.terminate()` عند مغادرة الصفحة، لأن ذاكرة WASM المحجوزة لا تنكمش بالحذف.

### قاعدة مطابقة مجاميع الآباء
- `group_by` + `sum` يطابق كل ما هو جمعي (ومنه التقرير مع `show_net_values=0`).
- للأزواج المصفّاة: الصافي الموقَّع بتعبير في المحرك، ثم:
  - العرض الشجري «كما هو»: صفوف التقرير كما أعادها (ii).
  - بعد إعادة التجميع أو الفلترة: (iii) داخل المحرك كلياً، أو (i) باستثناء موثق. **يحتاج قراراً.**
- الإجمالي = مجموع صفوف العمق 1 بعد التصفية، لا صف الجذر.
- التعابير في Perspective قبل التجميع دائماً؛ لا تعبير بعد التجميع.

### ما يجب تغييره في `docs/brief.md`
1. **الحد الأقصى للصفوف:** «100,000 افتراضياً، قابل للرفع حتى 200,000» بدل «يُحدَّد من التجارب / المؤقت 50,000»، مع الإحالة إلى هذا الملف.
2. **جدول المكتبات، سطر Perspective:** طريقة التحميل المثبتة (JS في bundle، و wasm و worker أصول ثابتة من نفس الأصل، و worker نملك مقبضه).
3. **جدول المكتبات، سطر `regular-table`:** «RTL عبر محوّل خاص بنا؛ الإصدار مثبّت بالضبط ويُعاد اختبار RTL عند الترقية».
4. **هدف الذاكرة:** إضافة «يُنهى الـ worker عند مغادرة الصفحة» و «التحميل على دفعات».
5. **هدف مطابقة الإجماليات / قاعدة لا حساب خارج المحرك:** نص القرار في §6.6 (أيّ البديلين للأزواج المصفّاة).
6. **المتصفحات:** المختبَر فعلاً Chromium فقط؛ Firefox و Safari معلّقان.
7. **قاعدة «لا تحذيرات في console»:** استثناء أو قرار بخصوص تحذير Perspective في غير Chrome (§4.1).
8. **المبدأ المعماري، سطر التطبيع:** المحوّل مسؤول عن تحويل كل قيمة إلى نوعها أو `null` قبل التحميل، و `Int` يُحمَّل `float` (§7.12).

## أسئلة مفتوحة
1. **Desk:** لم يُختبر التحميل داخل صفحة Desk لغياب حساب. شرط القبول في `docs/phases/phase-1.md` غير متحقق حرفياً.
2. **Firefox و Safari:** لم يُختبر شيء فيهما. يلزم `sudo npx playwright install-deps` على الخادم، أو جهاز آخر. ومعهما: تحذير `Unknown browser detected`، ومعالج العجلة الخاص بـ Safari مع محوّل RTL (§2.5).
3. **أيّ بديل للأزواج المصفّاة بعد إعادة التجميع:** (iii) أم (i)؟ (§6.6)
4. **الشجرة غير المنتظمة مع `group_by`:** إخفاء عقد `null` (§6.7). هل يُعتمد جدول العقد المسطح (ii/iii) لكل التقارير الشجرية؟
5. **مصدر ملفات wasm في الإنتاج:** مسار `node_modules` المربوط رمزياً (المجرَّب) أم نسخها إلى `public/` بسكربت `build` (غير مجرَّب)؟
6. **`bench build`:** يعيد 0 عند الفشل ويترك `assets.json` يشير إلى CSS محذوف (§1.2). يلزم فحص بعد البناء في إجراءات النشر.
7. **عمود النهاية المثبّت:** هل يستحق كلفة العنصر المستقل و `view` الثاني؟
8. **التمرير الجزئي الأفقي في RTL** (`sub-cell-scrolling.css`): لم يُجرَّب.
9. **CSP على `/assets`:** إن أُرسلت على ملف الـ worker نفسه، هل يكفي `'wasm-unsafe-eval'`؟ لم يُجرَّب.
10. **الفلاتر السريعة بتعابير منطقية:** تحتاج تصميماً يتجنب النصوص العربية الحرفية (§7.6) و `filter_op: "or"` (§7.8).
11. **أثر `worker.terminate()` على ذاكرة العملية** لم يُقَس (§3.3).
12. **أداء أجهزة المستخدمين:** كل الأرقام من خادم بأربع أنوية وتحت حمل. لا قياس على حاسوب مكتبي عادي أو هاتف.
13. **`System Settings.max_report_rows`** (100,000 على الموقع): رفع حد التطبيق فوقه يحتاج تعديله أيضاً (ADR-009).
