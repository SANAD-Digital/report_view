# ADR-020: إعدادات الطباعة المحفوظة (Print Preset): خاصة أو عامة، تُحفظ وتُختار وتُعدَّل

- الحالة: مقبول
- التاريخ: 2026-10-21

## السياق
- طلب صاحب المشروع (2026-10-21): «نمط الطباعة: المستخدم عمل إعدادات طباعة مخصصة، اعمل زر حفظ وخياراً عاماً أو خاصاً، فإذا أردت نمطاً آخر أو تعديل شيء أو حذفه حسب العمل أحفظ وأختار وأعدّل وأحفظ نسخة جديدة… استخدم ما في Frappe إن خدمك وإلا فاعمل DocType. هذه الميزة موجودة في Frappe للفلاتر وإعدادات القوائم، انظر هل تصلح».
- إعدادات الصفحات اليوم مجموعة واحدة لكل مستخدم وهدف في `frappe.model.user_settings` (مفتاح `pages`): `Report View:<report>` للتقرير (ADR-014)، `Report View Print:<doctype>` للمستند (ADR-017)، `Report View Print:Custom:<format>` للمخصص (ADR-019). لا أسماء، ولا مشاركة، ولا رجوع إلى مجموعة سابقة إلا «استعادة الافتراضي».
- في Frappe: `List Filter` (`filter_name`, `reference_doctype`, `for_user` فارغ = عام، `filters` JSON) هو نمط «فلاتر محفوظة» في القوائم، و`User Settings` لإعدادات القوائم (غير مسماة، لمستخدم واحد).

## الخيارات
1. `List Filter` نفسه: مربوط بفلاتر قائمة DocType واحد (`reference_doctype` إلزامي، والقائمة تقرأ `filters` على أنها فلاتر)؛ إعدادات الطباعة ليست فلاتر، والتقرير ليس DocType، ولا فيه «افتراضي» ولا وصف.
2. `User Settings`: لمستخدم واحد ولا يُشارك ولا يُسمى.
3. **DocType جديد `Print Preset` على نمط `List Filter`** (نفس اصطلاح `for_user`).

## القرار
الخيار 3.

### الحقول (وحدة Report View، التسمية `hash`، العنوان `preset_name`)
| الحقل | النوع | المعنى |
|---|---|---|
| `preset_name` | Data، إلزامي (≤ 140) | الاسم؛ لا يتكرر في نفس الجمهور والنوع والهدف |
| `for_user` | Link User | فارغ = عام لكل المستخدمين؛ محدد = خاص بهذا المستخدم (= المالك دائماً) |
| `is_default` | Check | الافتراضي لجمهوره وهدفه |
| `context` | Select: Report / Document / Custom | نوع الطباعة |
| `report` / `reference_doctype` / `print_format` | Link | الهدف حسب النوع؛ فارغ = لكل التقارير / كل أنواع المستندات / كل القوالب المخصصة. الحقلان الآخران يُفرغان عند الحفظ؛ `print_format` يجب أن يكون قالباً مخصصاً |
| `settings` | JSON، إلزامي | كائن إعدادات الصفحات (مفاتيح `DEFAULT_SETTINGS` ما عدا `zoom`) |
| `description` | Small Text | وصف اختياري |

### الصلاحيات
- **DocPerm**: System Manager كل شيء؛ Report Manager قراءة وإنشاء وكتابة وحذف؛ Desk User قراءة (بلا `if_owner`، حتى يقرأ العامة) وصف ثانٍ بـ `if_owner` للإنشاء والكتابة والحذف. لا `share` (كما في ADR-010).
- **من ينشر (يجعل الإعداد عاماً، ويعدّل العام أو يحذفه أو يجعله افتراضياً)**: System Manager أو **Report Manager** (`PUBLISH_ROLES`). فحصنا الأدوار على acc.dev: «Print Manager» غير موجود، و«Report View Manager» المذكور في ADR-010 لم يُشحن؛ «Report Manager» دور Frappe القياسي لمن يدير التقارير، وهو الأقرب. Administrator ينشر دائماً.
- **الخصوصية** بثلاث طبقات كما في العروض المحفوظة (ADR-010)، والقواعد في `report_view/core/print_presets.py`:
  - `permission_query_conditions`: القوائم = العامة + خاصة المستخدم نفسه.
  - `has_permission`: الخاص لا يراه ولا يعدّله إلا `for_user` المخزّن، **حتى System Manager** (CLAUDE.md: «الخاصة لا يراها ولا يعدّلها إلا مالكها»)؛ العام يقرؤه الجميع ولا يكتبه إلا ناشر؛ طلب يجعل `for_user` مستخدماً آخر مرفوض. «المخزّن» لا قيمة الطلب: REST يطبّق التعديلات قبل الفحص (ADR-010).
  - `validate` في المتحكم (يعمل مع REST أيضاً): الخاص لمالكه المخزّن فقط، والتحويل إلى عام لناشر، والعام إلى خاص لمن أنشأه فقط (فلا يصير إعداد عام خاصاً بشخص لا يراه أحد غيره)، والإعدادات بالتحقق أدناه، والاسم غير مكرر.
- **الواجهات** `report_view/api/print_presets.py` تبدأ كلها بفحص الهدف (`guard_target`؛ `delete` و `set_default` بهدف الإعداد نفسه، والإعداد العام لكل الأهداف بلا هدف يُفحص غير صلاحية الإعداد، وCustom العام بحارس القالب المرسل): التقرير بـ `guard_report` + `guard_print`، نوع المستند بصلاحية `print` عليه، القالب المخصص بـ `guard_custom_format`؛ ثم صلاحية `Print Preset` (`read` / `create` / `doc.check_permission`). القراءة بـ `frappe.get_list` والكتابة بـ `doc.save` / `doc.insert` / `doc.delete`. لا `ignore_permissions` ولا `set_user`.

### التحقق من الإعدادات في الخادم (`clean_settings`)
- كائن JSON، ≤ 32 KB، مفاتيح معروفة فقط (`SETTINGS_KEYS` = مفاتيح `DEFAULT_SETTINGS` في `pages_view.js` بلا `zoom`؛ اختبار `tests/js/print_presets.test.mjs` يفشل إن اختلفت القائمتان)، وقيم بسيطة: نص ≤ 2000، رقم محدود، منطقي، قائمة نصوص ≤ 500 (الأعمدة المخفية)، أو صندوق `{top,bottom,start,end}` بأرقام. غير ذلك `RVInvalidInput`.
- المتصفح يعيد فحص كل قيمة عند التطبيق بـ `sanitize_settings`، فالخادم يحرس الشكل والحجم والمتصفح يحرس المعنى.
- `list` يعيد `keys`، والمتصفح لا يرسل إلا ما يعرفه الخادم: مفتاح جديد في الصفحات لم يُضف بعد إلى الخادم لا يكسر الحفظ (يُترك فقط).

### الافتراضي
- `is_default` واحد لكل (جمهور، نوع، هدف): افتراضي جديد يلغي السابق في نطاقه (`on_update`، كما تفعل Letter Head). الخاص افتراضي لصاحبه، والعام (يجعله ناشر) افتراضي للجميع.
- يُطبَّق **فقط حين لا توجد إعدادات محفوظة للمستخدم** لهذا الهدف (أول فتح). الترتيب: افتراضي المستخدم الخاص لهذا الهدف، ثم الخاص لكل الأهداف، ثم العام لهذا الهدف، ثم العام لكل الأهداف.
- مستخدم لا ينشر ويريد إعداداً عاماً افتراضياً له: يطبّقه مرة فيُحفظ اختياره مع إعداداته (أدناه)، أو يحفظ نسخة خاصة ويجعلها افتراضية.

### التطبيق والمفاتيح الخاصة بالهدف
- تطبيق إعداد = `sanitize_settings(preset.settings)` فوق الإعدادات القياسية للموقع (المسار نفسه الذي تسلكه «استعادة الافتراضي»)، ثم فحص الاختيارات المسماة على خيارات هذه الصفحة (`check_choices`: الترويسة، قالب الطباعة، رأس الطباعة، التوقيع، اللغة؛ ما لا يُعرض هنا يعود فارغاً، وبلا ترويسة تؤخذ ترويسة الشركة)، ثم إعادة التقطيع. التكبير يبقى كما هو.
- **مفاتيح الهدف** (`TARGET_KEYS`): `hidden` (أعمدة تقرير بعينه) و`template` (قالب طباعة تقرير أو نوع مستند أو قالب مخصص بعينه). إعداد «لكل التقارير/الأنواع/القوالب» **لا يحفظها ولا يطبّقها**: يبقى للهدف الحالي أعمدته وقالبه. إعداد «لهذا الهدف فقط» يحفظها ويطبّقها (ولا يظهر إلا لهدفه). وما بقي من اختيارات مسماة يتحقق منه `check_choices`؛ بقية القيم (الورق، الهوامش، الألوان، الخط…) عامة بطبيعتها و`sanitize_settings` يفحصها.
- **التذكّر**: اسم الإعداد المطبّق يُحفظ مع إعدادات المستخدم في `user_settings` (`pages.preset`)؛ عند الفتح مرة أخرى يظهر اسمه، ونقطة «تغيّر» إن اختلفت الإعدادات عنه. «استعادة الافتراضي» تلغي الإعداد المطبّق.

### الواجهة (شريط الأدوات، ADR-014)
- في سطر الرأس بين عدد الصفحات و«استعادة الافتراضي»: زر «الإعداد: <الاسم | الافتراضي>» ونقطة كهرمانية حين تختلف الإعدادات الحالية عن المطبّق.
- قائمته بنمط `.rv-print-pop` نفسه (ورقة من أسفل الشاشة على الهاتف، مع الستار وزر الإغلاق وEsc): «الافتراضي»، ثم «إعداداتي» و«إعدادات عامة» (لكل صف: الاسم، نطاقه «هذا التقرير / كل التقارير» والوصف، شارة خاص/عام، نجمة الافتراضي — زر لمن يملك التعديل)؛ النقر يطبّق. تحتها: «حفظ» (يكتب الإعدادات الحالية في المطبّق، لمن يملك تعديله وحين يتغير شيء)، «حفظ كنسخة جديدة…» (الاسم، من يراه — لمن ينشر فقط —، «لهذا التقرير فقط / لكل التقارير» أو ما يقابلها للمستند والمخصص، الوصف، اجعله الافتراضي)، «تعديل…» (الاسم، من يراه، الوصف، الافتراضي)، «حذف» (تأكيد). النوافذ `frappe.ui.Dialog` والتأكيد `frappe.confirm`.
- الكود: `views/print_presets.js` (`PresetControl` والدوال النقية)؛ `pages_view.js` ينشئه في الرأس، يطلب القائمة مع الإعدادات والخيارات (`prefetch`)، ويطبّق الافتراضي في `load_setup`، ويحفظ اسم المطبّق في `save_settings()`. المضيفون الثلاثة يعطون الهدف بدالة صغيرة `pages_preset_target()`: `{context: "Report", target: report}` في `index.js`، و`{context: "Document", target: doctype}` و`{context: "Custom", target: format}` في `doc_print.js`. مضيف بلا هذه الدالة لا يُظهر الزر.

## عقد الواجهة (API)
| الدالة | الطريقة | المعاملات | يعيد |
|---|---|---|---|
| `report_view.api.print_presets.list` (الدالة `list_presets`؛ `list` اسمها القديم يبقى لأن الشريط وحزمة الفحص البصري تناديانه) | GET | `context`, `target` | `{mine: [row], public: [row], can_publish, keys}` — هذا الهدف أولاً ثم العامة لكل الأهداف |
| `report_view.api.print_presets.save` | POST | `context`, `target`, `preset_name`, `settings` (JSON)، `public`, `for_all`, `description`, `is_default`، و`name` (تعديل: ما يُرسل فقط يتغير) أو `name` + `as_new=1` (نسخة) | `row` |
| `report_view.api.print_presets.delete` | POST | `name` | `{name}` |
| `report_view.api.print_presets.set_default` | POST | `name`, `value` (1/0) | `row` |

`row` = `{name, preset_name, public, is_default, context, target, specific, description, settings, can_edit, owner_name, modified}`. `save` و `delete` و `set_default` محدودة بـ 60 طلباً في الدقيقة لكل مستخدم، و `list` بـ 120 (`_rate_limit`).

## العواقب
- DocType جديد يُثبَّت بـ `bench --site <site> reload-doc report_view doctype print_preset` (أو migrate)، والـ hooks تحتاج `clear-cache`، ودوال `api/print_presets.py` تحتاج إعادة تشغيل الخادم حيث كان `report_view.api` محمّلاً.
- Administrator يتجاوز الـ hooks بالاسم في Frappe (`permissions.py`): يستطيع فتح إعداد خاص بالاسم عبر REST، كما في ADR-010 (حساب صيانة). القوائم تُصفّى له بالـ pqc.
- System Manager لا يرى الإعدادات الخاصة لغيره ولا يعدّلها؛ يرى العامة ويعدّلها ويحذفها.
- مفتاح جديد في `DEFAULT_SETTINGS` يجب أن يُضاف إلى `SETTINGS_KEYS` (يفشل اختبار JS حتى يُضاف)؛ حتى يُضاف لا يُحفظ في الإعدادات المحفوظة ولا يكسر شيئاً.
- الاختبارات: `report_view/tests/test_print_presets.py` (الخصوصية بين مستخدمَين، العام للجميع، من ينشر، الافتراضي الواحد، التحقق، النسخ والتعديل والحذف، فحص الهدف أولاً)، `tests/js/print_presets.test.mjs`، ثلاثة اختبارات «print presets» في `tests/visual/screens.spec.js`، و`tests/site/print_presets.cjs` على الموقع.
